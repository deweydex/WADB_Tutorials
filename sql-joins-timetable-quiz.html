Build a Timetable

SQL Joins Quiz

The college needs a weekly timetable. The information lives in nine separate tables, and no single table holds a whole timetable. A JOIN combines rows from two tables by matching the ID columns that link them. You will write joins of growing size, and in the last two tasks you will build a real timetable for one student. The data is already loaded, so you only write SELECT queries.

This quiz assumes you have met SELECT, WHERE and ORDER BY. If those are new, start with the Plushies quiz.

Words about the college

Program: a course of study that a student follows, such as Computer Science.

Module: one subject inside a program, such as Programming Fundamentals. Several programs can share the same module.

Section: one group of students who take a module together. Programming Fundamentals has a Section A and a Section B, and each section has its own teacher.

Event: one class meeting that repeats every week, such as Section A's lab on Tuesday at 13:00. The timetable is the list of events.

Enrolment: the record that one student takes one section.

Lead teacher: the teacher in charge of a program. This teacher may also teach sections.

Words about databases

Table: a grid that holds one kind of thing, such as students.

Row: one item in a table, such as one student.

Column: one fact that every row stores, such as first_name.

ID (primary key): the number in the id column that identifies one row. No two rows in a table share an ID. The tables list marks it PK.

Foreign key: a column that stores the ID of a row in another table. The column students.program_id holds the ID of the student's program. The tables list marks it FK.

Join: a way to put rows from two tables side by side by matching a foreign key with the ID it points to.

Bridge table: a table that holds two foreign keys and nothing else. We need one when each row on one side can match many rows on the other side. A module belongs to many programs, and a program has many modules, so program_modules sits between them. A student takes many sections, and a section has many students, so enrolments sits between them.

Reading one event

The events table stores only numbers. Event 7 holds section_id = 1, room_id = 6, day_of_week = 2 and start_time = '13:00'. We follow each ID to the table it points to.

section_id = 1 leads to section 1. That row says Section A of module 1, taught by teacher 1.

module_id = 1 leads to the module Programming Fundamentals. room_id = 6 leads to the room Lab B.

Put together, event 7 reads: Programming Fundamentals, Section A, on Tuesday at 13:00 in Lab B. A join does this lookup for every row at once.

The day_of_week column counts from 1 (Monday) to 5 (Friday). The start_time column is text in 24-hour form, such as '09:00'.

Why Join?

Each fact is stored once, in the table where it belongs. A room name lives in rooms, and an event only stores a room_id, which is a foreign key. A join follows that ID to bring the room name back next to the event.

Read a join in three steps. First decide which table holds the thing you want to list. Then follow the ID columns from table to table until you reach every column you need. Finally write one JOIN for each step.

INNER JOIN

Keeps only the rows that have a match in both tables. Writing JOIN alone means INNER JOIN.

Syntax:

SELECT columns
FROM table_a
JOIN table_b ON table_a.b_id = table_b.id;

Example:

-- Events held in the labs
SELECT rooms.room_name,
       events.day_of_week,
       events.start_time
FROM events
JOIN rooms ON events.room_id = rooms.id
WHERE rooms.room_type = 'Lab';

Aliases

An alias is a short name for a table. Write it after the table name, then use it everywhere in the query.

SELECT r.room_name, e.start_time
FROM events e
JOIN rooms r ON e.room_id = r.id;

When two tables share a column name, such as first_name in students and teachers, write t.first_name so SQL knows which one you mean. You can also rename a column in the output with AS.

Joining Many Tables

Add one JOIN line per link. Each ON compares an ID that already appears in the query with the matching ID in the new table.

-- Which rooms does each section use?
SELECT s.section_name, r.room_name
FROM sections s
JOIN events e ON e.section_id = s.id
JOIN rooms r  ON e.room_id = r.id;

Bridge tables

A bridge table such as program_modules or enrolments exists only to link two other tables. It holds two foreign keys and nothing else. To get from one side to the other, join through it.

LEFT JOIN

Keeps every row from the left table, even when no row on the right matches. The right-hand columns are NULL for those rows.

-- Every room, with how many events it hosts
SELECT r.room_name, COUNT(e.id) AS event_count
FROM rooms r
LEFT JOIN events e ON e.room_id = r.id
GROUP BY r.id;

Counting with LEFT JOIN

COUNT(e.id) ignores NULL, so an unused room shows 0. COUNT(*) would count the empty row and show 1.

ON and WHERE

ON says how two tables connect. WHERE says which of the joined rows you want. Keep these two jobs separate and your queries stay easy to read.

WARNING

If you forget the ON, SQL pairs every row of one table with every row of the other. Two tables of 22 and 6 rows give 132 rows. A result that is far too large is the sign of a missing join condition.

Grouping and Counting

FunctionPurpose
COUNT(col)Counts rows where col is not NULL

GROUP BYOne result row per group
-- Total teaching minutes per section
SELECT section_id, SUM(duration_minutes)
FROM events
GROUP BY section_id;

Text, CASE and Times

Join text with ||

SELECT first_name || ' ' || last_name AS full_name
FROM teachers;

Choose a value with CASE

SELECT CASE capacity
         WHEN 16 THEN 'Small'
         ELSE 'Large'
       END AS size
FROM rooms;

Add minutes to a time

SELECT time('09:00', '+90 minutes');
-- 10:30:00

SELECT time(start_time, '+' || duration_minutes || ' minutes')
FROM events;

The time() function returns hours, minutes and seconds, such as 10:30:00. The checker accepts that form.

Common Mistakes

  1. No ON clause - the result has far too many rows.
  2. Ambiguous column name - write alias.column when two tables share a name.
  3. Joining the wrong IDs - compare a foreign key with a primary key, such as e.room_id = r.id.
  4. Using JOIN when you need LEFT JOIN - rows with no match vanish.
  5. Sorting day names - sort by day_of_week, not by the name.
  6. Missing quotes - text needs single quotes: 'Maeve'.

Tips for Success

  • Build a query one join at a time. Run it after each join and look at the rows.
  • Click a table name above the editor to see what a table contains.
  • Start with SELECT * to see every joined column, then pick the ones you need.
  • Check the row count under each result against what you expect.
